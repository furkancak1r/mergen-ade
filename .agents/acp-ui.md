# OpenCode ACP UI Guidelines

## OpenCode ACP UI Guidelines
- **Composer must be a compact rounded capsule.** The chat input area should be a rounded rectangle (`ACP_COMPOSER_CAPSULE_RADIUS = 12.0`, fill `Color32::from_rgb(27,27,27)`, no visible stroke) containing: a scrollable prompt editor above a bottom control row with a circular `+` button on the left, a compact Plan mode pill only when plan mode is active, a combined model+effort selector, and a circular send/stop button on the far right. This matches the Cursor composer visual style.
- **Composer has one right-side action button.** Do not render separate Send and Stop/Cancel buttons in the ACP composer or a running-state Cancel button in the ACP header. The single circular right-side button is `Send` when draft text or attachments exist, including while an ACP turn is running so the draft can queue Smart Input-style. When the draft is empty and the ACP turn is running, the same button changes to `icons::X` Stop, calls `session/cancel`, clears local running state, and leaves queued prompts intact.
- **Esc stops the active ACP turn.** While the visible ACP chat is running and has a `sessionId`, plain `Esc` must use the same stop path as the single Stop action state. Do not consume modified Escape shortcuts, and do not override popup/modal/context-menu Escape handling.
- **Queued ACP prompt rows must be readable and left-aligned.** Render local queued prompts as compact 44px+ rows with normal-size preview text near the `Queued`/mode metadata. Do not use tiny `.small()` preview text or stretch a short prompt across the full viewport so it appears centered.
- **Capsule must be painted manually with a single `painter().rect()` call.** Do not use `egui::Frame::none().fill(...).stroke(...).rounding(...)` because egui's default background can bleed through the anti-aliased corners, producing a dark halo. Instead, call `composer_ui.painter().rect(capsule_rect, radius, fill, Stroke::NONE)` and then create a child UI with `capsule_rect.shrink2(...)` for the content. This ensures the entire capsule area is filled with a single, consistent color and no visible border artifact appears at the corners.
- **ComboBox inside the capsule must use local `ui.scope` widget visual overrides.** The default egui widget visuals (inactive fill ≈ rgb(30,30,30), stroke ≈ rgb(46,46,46)) clash with the capsule fill (rgb(27,27,27)). Wrap the ComboBox in a `ui.scope` and override `visuals.widgets.inactive`, `hovered`, `active`, and `open` fill colors to match the capsule tone, and set their `bg_stroke` to `Stroke::NONE`. This prevents the model selector button from looking like a different-colored patch at the rounded edges.
- **Default/build mode must not render mode text.** The internal/default `build` mode must not display `Normal`, `Default`, or any other mode label in the ACP chat UI. Composer and queued-message rows render a mode label only for `plan` (`Plan`) or a non-build custom mode. The configurable mode-toggle shortcut still flips `plan` ↔ `build`; clicking the visible `Plan` pill returns to `build`.
- **Model + effort selector must be a single compact dropdown.** Instead of separate ComboBoxes for model and effort, the composer should show one combined selector displaying the current model name and effort name (e.g. `Sonnet 4 No Thinking`). The dropdown popup should still have separate Model and Effort sections so the user can change each independently.
- **Status row must appear below the composer.** A thin status row (22px, muted text) should show the current git branch (from `source_control_state`), the `Local` label, and the ACP session status text (`Idle`, `Running...`, etc.). No fake context percentage or token usage should be displayed unless real data is available from the ACP protocol.
- **Composer stack geometry must come from helper functions.** Use `acp_composer_height()` and `acp_composer_rects()` for slash hints, capsule, attachment chips, and permission cards. Do not hand-code parallel `24.0`, `4.0`, or `60.0` offsets in `draw_acp_chat_panel`.
- **Permission cards render below the composer; slash hints render above the input.** Permission cards are drawn below the capsule, while slash command hints are drawn in a dedicated area above the input capsule so they never overlap attachments, permission cards, or the status row.
- **Long ACP prompt input grows upward and then scrolls.** The prompt editor lives above the footer controls, grows with wrapped content up to `ACP_COMPOSER_INPUT_MAX_HEIGHT`, and then scrolls internally. The bottom footer row (`+`, mode pill, model+effort selector, send/stop button) must remain bottom-anchored and must never be overlapped by prompt text.
- **Enter submits, Ctrl+Enter inserts newline.** The single-line multiline text edit must keep the existing `return_key(Ctrl+Enter)` behavior so plain Enter sends the prompt while Ctrl+Enter adds a newline.
- **Composer input text must be vertically centered when single-line.** The `TextEdit::multiline` inside the chat capsule should use `.vertical_align(Align::Center)` so that short hint text (e.g. `Waiting for session...`) and single-line typed text sit cleanly inside the editor; long content scrolls in the editor above the footer controls.
- **Mode pill must not show a `×` icon.** When visible, the mode pill should display only the mode name (`Plan` for plan mode), not a close/dismiss icon. The pill itself is clickable.
- **`+` button opens a file picker for attachments.** Clicking the circular `+` button on the left of the composer opens `rfd::FileDialog::new().pick_files()`. Selected file paths are stored in `session.attachments` and rendered as removable chips below the composer. Additionally, each selected file is inserted into the composer input as a `@file_name` mention (using the file's basename) so the user can see which files are attached inline. The prompt can be sent even if the text input is empty, as long as attachments exist.
- **Removing an attachment chip also removes its mention from the input.** When the user clicks an attachment chip to remove it, the corresponding `@file_name` mention is removed from `session.prompt_input` using `remove_mention_from_input()`. This keeps the input text in sync with the active attachment list. If the user manually edited the mention text, the helper removes only the last exact `@file_name` match.
- **Attachment chips must be visible and not clipped.** The composer height is dynamically expanded by `ACP_COMPOSER_BELOW_CAPSULE_GAP + ACP_COMPOSER_ATTACHMENT_ROW_HEIGHT` when `session.attachments` is non-empty. Chips use a brighter text color (`rgb(180,180,180)`), a slightly darker fill (`rgb(40,40,40)`), and a more visible stroke (`rgb(90,90,90)`) so they are readable against the dark background. The attachment chip row is rendered in a separate child `Ui` with a fixed height below the capsule, and a horizontal `ScrollArea` prevents overflow when many files are attached.
- **Chat history must show the full prompt including attachments.** The `AcpChatMessage::User` text pushed to `session.messages` must be the final `build_acp_prompt_text` output, not the raw input text alone. This ensures the user sees exactly what was sent to the agent, including the "Attached file paths:" block.
- **Attachments are path-only; file contents are never injected.** The prompt builder appends only the full file path(s) under an "Attached file paths:" label. The AI agent reads the file on demand if needed. This prevents context bloat from large file contents.
- **`send_prompt` must not duplicate attachments.** The app builds the full prompt text once via `take_acp_composer_submit()` / `build_acp_prompt_text(text, &attachments)` and then calls `send_prompt` with `session.attachments` already empty (via `std::mem::take`). This prevents `send_prompt` from appending a second attachment block because the payload already contains the complete text.
- **Plain Enter only sends when the input has focus.** Do not trigger send on `response.lost_focus()`. When the file picker opens, the `TextEdit` loses focus but the prompt must not be sent automatically. The send condition must be `plain_enter && response.has_focus() && can_send`, where `can_send` comes from `acp_composer_can_send()`.
- **Attachment picker must not auto-send.** Adding a file via `rfd::FileDialog` only appends paths to `session.attachments` and requests a repaint. No message is sent to the chat history or the ACP server until the user explicitly presses Enter or the Send button.
- **Tab toggles plan/default mode by default.** When the ACP chat composer is active and no popup is open, pressing `Tab` (with no modifiers) toggles between `plan` and the default/internal mode (`build`) via `session/set_config_option`. The Tab event is consumed and not passed to the TextEdit so it does not trigger focus traversal.
- **ACP mode/model binding is default-on and Settings-controlled.** Settings > OpenCode exposes `Bind ACP model to mode` (`OpenCodeModelConfig::acp_bind_model_to_mode`, default `true`). When enabled, every ACP mode change path (Plan pill, Tab shortcut, startup defaults, `current_mode_update`, config option updates, queued prompt dispatch) must apply the mode's configured model before sending: `plan` uses the Plan model plus Plan effort, and `build` uses the active build model slot. When disabled, changing mode must preserve the user's current ACP model/effort selection.
- **ACP mode toggle shortcut is configurable from Settings.** Settings > Shortcuts contains a dedicated "OpenCode ACP Mode Toggle" card where the user can enable/disable the shortcut, record a custom key, and set Ctrl/Alt/Shift/Cmd modifiers. The default is `Tab` with no modifiers. The config is stored in `AppConfig::acp_mode_toggle_shortcut` and persists across sessions.
- **Composer layout must reserve space for right-side controls.** Use `acp_composer_footer_widget_rects()` and `acp_composer_footer_layout()` as the source of truth for the bottom control row: send stays right-aligned and model width is dynamically clamped between `ACP_COMPOSER_MODEL_WIDTH_MIN` and `ACP_COMPOSER_MODEL_WIDTH_MAX`. Prompt text must be laid out in the editor rect above the footer, not inside the footer row.
- **Composer footer spacing is optical, not just rect-based.** The visible model label starts at `acp_composer_model_label_left(model_rect)`, which includes `ACP_COMPOSER_MODEL_BUTTON_PADDING_X`. When tuning the `+`, `Plan`, and model selector spacing, compare the visible label start against neighboring widget edges; do not rely only on raw `model_rect.left()`.
- **Model selector label width is layout-driven.** Long model names should not be manually truncated in the data model. `acp_composer_model_label()` returns the full selected label, `acp_composer_model_desired_width()` caps the button width, and egui handles visual clipping within the ComboBox. The selected model label must not contain extra glyphs such as `▾` or `🔍`.
- **Model selector button must be vertically aligned with the input field.** The `ComboBox` button should match the text input height by temporarily setting `ui.spacing_mut().interact_size.y = ACP_COMPOSER_CONTROL_HEIGHT` inside a `ui.scope` before the `ComboBox`. The `ComboBox::height()` method only controls the popup menu max height, not the button height. The input field should use the same `ACP_COMPOSER_CONTROL_HEIGHT` constant for sizing so the capsule row looks uniform.
- **Composer model dropdown shows only favorited models.** The `Model` section inside the dropdown popup must filter `model_opt.options` against `acp_favorite_models`. If the favorites list is empty, the dropdown shows `"No favorite models. Add favorites in Settings > OpenCode."`. Search inside the dropdown still works, but only over the favorited subset. The selected model label must not contain extra glyphs such as `▾` or `🔍`.
- **ACP model options are cached on `ConfigOptionUpdate`.** When `process_acp_chat_events` receives a `ConfigOptionUpdate` with `option.id == "model"`, it merges the option entries into `config.opencode.acp_known_models` via `merge_acp_known_models()`. This keeps model names visible in Settings > OpenCode even after the ACP session closes.
- **Settings > OpenCode contains an "ACP Favorite Models" card.** The card renders all `acp_known_models` with a star icon toggle. Favorited models use a bright star color (`rgb(220,180,60)`); unfavorited models use muted text. Toggling updates `config.opencode.acp_favorite_models` and triggers `note_opencode_change()` so the change persists. When no known models exist yet, the card shows a hint to open an ACP chat.
- **Attachment chip row must not overlap the capsule.** The capsule row must be explicitly allocated in the parent `composer_ui` (e.g. via `allocate_rect`) before the chip row is drawn. The chip row must use `acp_composer_rects().attachment_rect`, which starts after `capsule_rect.max.y + ACP_COMPOSER_BELOW_CAPSULE_GAP`, not `composer_ui.available_rect_before_wrap()` which may return the same top coordinate if the capsule was a `new_child` that did not advance the parent cursor.
